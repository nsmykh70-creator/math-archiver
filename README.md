# math-archiver — алгебраическое сжатие данных

**Идея:** данные = формула = (затравка / модель) + (операции / исключения).
Восстановление — детерминированное применение формулы, поэтому всё строго
без потерь: каждый кандидат сжатия перед записью проверяется побайтовым
roundtrip, и если хотя бы байт не совпал — кандидат отбрасывается.

Это реализация концепции «одной формулы вместо данных» и трёхслойной
архитектуры сжатия:

1. **Слой 1 — нормализация представления.** Всё приводится к UTF-8-тексту
   или компактным числам; «дорогие» формы записи убираются.
2. **Слой 2 — доменно-осознанная формула.** Хранится только то, что нельзя
   вывести: для равенств — операнды вместо результата (или наоборот), для
   журналов состояний — дельты вместо полных строк, для текста — литералы,
   не совпавшие с предсказанием (позиции пропусков — явной битовой картой).
3. **Слой 3 — статистическое сжатие без потерь.** На выбор: LZMA2 (xz,
   preset 6), zstd (уровень 3) или gzip (уровень 6) — бэкенд задаётся
   аргументом и записывается в заголовок кадра; распаковка определяется
   автоматически.

## Кодеки (слой 2)

| Кодек | Вход | Формула | Восстановление |
|---|---|---|---|
| `numeq` | независимые равенства `a op b = c` | кратчайшая из корректных форм: `27*761`, `32099+=61356`, `8072-=3906`, `^2=23415921` | результат вычисляется, операнд — обратной операцией, основание — целым корнем |
| `numseries` | журнал состояний `x op k = b` (цепочка) | затравка + `+26`, `*6`, `-33` (+ снапшоты `=значение` каждые N шагов) | последовательное применение шагов; снапшоты дают случайный доступ и локализуют порчу бита |
| `textcodec` | любой Unicode-текст (кириллица, CJK, арабский, эмодзи) | литералы + битовая карта пропусков; двухуровневый предсказатель «пара символов → символ», затем «символ → символ» | та же статистика, построенная только по литералам, на стороне декодера; без лингвистических предположений, поэтому работает для любых письменностей |
| `textlayer` | кириллический текст (схема V-byte из разбора skor-skeleton v1) | кириллица — 1 байт на букву (регистр сохранён), 36 частотных триграмм — 1 байт, латиница и ASCII — литеральные байты, прочий не-ASCII — RAW-блоки | конечный автомат: коды и ASCII не пересекаются, RAW копируется дословно |
| `varint` | целые литералы 5–24 цифр в любом тексте | 10 бит на группу из 3 цифр (база-1000, LSB-first): 24 цифры -> 11 байт вместо 24 | байтовый автомат; астральные символы и ведущие нули — слой честно отказывается |

Строки, не прошедшие проверку арифметики или выпадающие из модели, хранятся
дословно с префиксом `!` — кодеки никогда не теряют данные.

`lossy.py` содержит демонстрацию ПОТЕРЬНОГО «скелета» (гласные/огласовки) —
он **не входит** в контейнер и приведён только для оценки верхней границы
выигрыша.

## Формат контейнера MAF1 (14 байт заголовка, чтение для совместимости)

```
MAGIC 'MAF1' (4) | kind (1) | flags (1) | orig_len (8, big-endian) | тело
kind: 0 BIN, 1 NUM_EQ, 2 NUM_SERIES, 3 ALPHA_TEXT, 4 TEXT_IDEO
flags: 0 — как есть; 1 — xz; 2 — формула; 3 — формула + xz
```

## Формат контейнера MAF2 (15 байт заголовка + 2 байта CRC)

```
MAGIC 'MAF2' (4) | kind (1) | flags (1) | orig_len (8 BE) | backend (1)
| payload | CRC-16/CCITT (2, big-endian) над header+payload
flags (биты): 1 — формула; 2 — varint; 4 — payload сжат; 8 — textlayer
backend: 0 — xz (LZMA2); 1 — zstd; 2 — gzip
```

CRC-16/CCITT-FALSE (полином 0x1021, init 0xFFFF) покрывает заголовок и
нагрузку: порча ЛЮБОГО байта кадра, кроме самих байтов CRC, обнаруживается
на входе декодера до всякой распаковки. Конвейер записи:
данные -> [формула] -> [varint] -> [сжатие]; чтение — в обратном порядке.

Контейнер сам определяет тип данных (`detect_kind`), перебирает варианты,
проверяет каждый roundtrip-ом и выбирает минимальный. Случайные данные
(архивы, ключи, шум) честно распознаются как `BIN` и сохраняются как есть —
предел Шеннона обойти нельзя.

## Использование

```bash
# из корня репозитория
python -m algebraic compress input.txt output.maf2 [--snapshot 1000] [--backend xz|zstd|gzip]
python -m algebraic decompress output.maf2 restored.txt
python -m algebraic info input.txt

# тесты побайтового roundtrip: все кодеки, все письменности, три компрессора,
# property-тест (1000 случайных строк на LCG) и порча каждого байта кадра
python -m unittest discover -s tests -v

# бенчмарки
python benchmarks/bench.py [--quick]        # MAF1-методика: формула × xz
python benchmarks/bench_maf2.py [--quick]   # MAF2 × xz/zstd/gzip + 677647.fb2
```

`compress` печатает SHA-256 исходника, `decompress` — SHA-256 результата.
Совпали — файл восстановлен побайтово.

## Кадр .maf2 — бинарник, не текст

Открытый в текстовом редакторе кадр выглядит как кракозябры: куски фраз без
букв, «» и тире читаются, а на месте остальных символов — иероглифы и
редкие знаки. Это нормальное состояние СЖАТОГО файла, а не испорченные
данные: словарь-предсказатель хранит только символы, которые не смог
предсказать (на типичном тексте — 3–15% букв), а пропуски закодированы
управляющими байтами V-byte/varint, которые редактор рисует как редкий
Unicode. Декодер возвращает каждый пропущенный символ по тому же словарю и
проверяет длину и CRC-16 — результат всегда побайтово равен исходнику.
«Гласные удаляются» только из сжатого представления: при распаковке они
восстанавливаются автоматически, удалять их из модели не нужно.

Кадры старого формата MAF1 читаются текущим кодом тем же кодеком
(`textcodec` не менялся с первого коммита) — см. тест
`tests/test_maf1_compat.py`. У MAF1 нет CRC, поэтому при порче такого кадра
ошибка обнаружится только по несовпадению размера или проверке SHA-256.

Зависимостей нет в базовой поставке (только стандартная библиотека Python
3.10+); для бэкенда `zstd` дополнительно нужен пакет `zstandard`.

## UHC — Rust-ядро и веб-версия (WASM)

В репозиторий интегрирован прототип `uhc_web.zip` (Universal Hybrid Codec):
нативное Rust-ядро с zstd/BLAKE3/rayon (`uhc/uhc_workspace`), WASM-мост
(`uhc/uhc_web/wasm_bridge`) и веб-интерфейс. Режимы 1/2 для текста —
осознанно потерьный «скелет» (исправлен баг с проверкой BLAKE3, добавлены
6 тестов roundtrip). Подробности — в [uhc/README_RU.md](uhc/README_RU.md).

**Веб-версия приложения опубликована на GitHub Pages:**
https://nsmykh70-creator.github.io/math-archiver/ (исходники сайта — в `docs/`).

## Ограничения — предел Шеннона

Сжать без потерь можно только избыточность. Структурированные данные
(текст, журналы, таблицы, датчики) сжимаются в разы и десятки раз; случайные
байты (ключи, шум, уже сжатые архивы .zip/.mp4) — нет, и контейнер в этом
случае честно хранит их как есть (+14 байт заголовка).

## Roadmap

- пиньинь/ромадзи-нормализация CJK (слой 1) — с явным словарём омонимов;
- разложение иероглифов на ключи/радикалы (слой 2, большие массивы);
- канa-скелет для японского (слой 2, lossy — отдельно от контейнера);
- индекс снапшотов журнала для O(log n) случайного доступа;
- арифметическое кодирование как четвёртый бэкенд слоя 3;
- перенос текстового яруса textlayer/varint в Rust-ядро UHC.
